# VoiceAI Rooms

تطبيق غرف صوتية عربي RTL مبني بـ HTML/CSS/Vanilla JavaScript، مع خادم Node.js وSocket.IO واتصال صوتي WebRTC.

## ما تمت إضافته في هذه النسخة

- خادم Express يقدّم الواجهة وواجهات API.
- مزامنة قائمة الغرف وإنشاؤها على الخادم.
- دخول المستخدمين كضيوف إلى الغرف ومزامنة قائمة الموجودين.
- دردشة نصية فورية محفوظة مؤقتاً في ذاكرة الخادم.
- WebRTC لنقل الصوت بين المشاركين، مع خادم Signaling عبر Socket.IO.
- إعداد STUN افتراضي، وإمكانية ضبط TURN من متغيرات البيئة.
- ملف `render.yaml` للنشر على Render مع قرص دائم لملف الغرف.

## التشغيل محلياً

يتطلب Node.js 20 أو أحدث.

```bash
npm install
npm start
```

ثم افتح: `http://localhost:3000`

لا تستخدم `python -m http.server` لهذه النسخة؛ يجب تشغيل `server.js` حتى تعمل الغرف والاتصالات.

## النشر على Render

1. ارفع مجلد المشروع إلى مستودع GitHub.
2. من Render اختر **New → Blueprint** واربط المستودع.
3. سيقرأ Render ملف `render.yaml` وينشئ Web Service باسم `voiceai-rooms`.
4. بعد اكتمال النشر افتح رابط `onrender.com` الذي يوفره Render.
5. تحقق من `https://YOUR-SERVICE.onrender.com/api/health` ويجب أن يعرض `ok: true`.

ملف Blueprint يستخدم خطة Starter وقرصاً دائماً بحجم 1GB كي لا تضيع قائمة الغرف عند إعادة تشغيل الخدمة. قد تترتب تكلفة استضافة حسب أسعار Render الحالية.

## إعداد TURN (مهم لنجاح الاتصال عبر شبكات مختلفة)

تم إعداد STUN افتراضياً، لكنه لا يضمن الاتصال من كل شبكات الهاتف والراوترات. للحصول على موثوقية أفضل، احصل على بيانات TURN من مزود TURN موثوق، ثم أضف في Render → Environment:

- `TURN_URLS` — عنوان أو عناوين TURN مفصولة بفواصل، مثال: `turn:turn.example.com:3478?transport=udp,turns:turn.example.com:5349?transport=tcp`
- `TURN_USERNAME` — اسم مستخدم TURN.
- `TURN_CREDENTIAL` — كلمة مرور/اعتماد TURN.

تُقرأ هذه القيم من الخادم ولا تُحفظ داخل ملفات JavaScript العامة. بعد إضافتها أعد نشر الخدمة. لا تضع بيانات TURN أو مفاتيح AI في GitHub.

## اختبار الاتصال بين جهازين

1. افتح رابط Render على هاتف أول، وادخل باسم ضيف.
2. افتح الرابط نفسه على هاتف ثانٍ أو متصفح آخر، وادخل باسم مختلف.
3. ادخل الغرفة نفسها من الجهازين.
4. وافق على إذن الميكروفون في الجهازين.
5. اضغط «تشغيل الميكروفون» في كل جهاز وتحدث؛ استخدم سماعات لتجنب الصدى.
6. تحقق من ظهور المستخدمين في قائمة الغرفة ومن سماع الصوت في الطرف الآخر.

يجب فتح الموقع عبر HTTPS (Render يوفره تلقائياً) للسماح بالميكروفون على الهواتف.

## حدود هذه النسخة

- الدخول حالياً كضيف؛ لا توجد حسابات بكلمات مرور أو تحقق بريد أو استعادة حساب.
- لا توجد صلاحيات إدارية آمنة على الخادم حتى الآن؛ لوحة الإدارة الحالية محلية/تطويرية.
- الغرف تحفظ على القرص الدائم، لكن رسائل الدردشة وحالة الأعضاء تحفظ في ذاكرة الخادم وتُمسح عند إعادة تشغيله.
- الغرف الخاصة حالياً لا تطلب رمز دخول؛ اختيار «خاصة» في الواجهة ليس نظام حماية كاملاً.
- WebRTC الحالي يستخدم اتصال mesh: كل مشارك ينشئ اتصالاً مع كل مشارك آخر. مناسب لبداية واختبارات مجموعات صغيرة، وليس للتوسع الكبير. للمجموعات الكبيرة يُنصح بخادم SFU مثل LiveKit أو mediasoup.
- STUN وحده قد لا يكفي لبعض الشبكات. يلزم TURN موثوق للاعتمادية، ويجب اختبار مزود TURN من شبكات الهاتف والبلدان المستهدفة.
- لم يتم اختبار اتصال صوتي حقيقي بين جهازين من داخل بيئة البناء هذه؛ يجب تنفيذ خطوات الاختبار أعلاه بعد النشر.
- مفاتيح مزودي AI لا تزال في إعدادات المتصفح في النسخة الحالية؛ لا تستخدم مفاتيح حقيقية على موقع عام قبل نقل طلبات AI إلى Backend آمن.

## ملفات مهمة

- `server.js` — Express وSocket.IO وواجهات الغرف والإشارات.
- `js/realtime.js` — Socket.IO وWebRTC في المتصفح.
- `js/voice.js` — الميكروفون ومؤشر الصوت.
- `js/rooms.js` — تحميل وإنشاء الغرف.
- `render.yaml` — إعداد النشر.
- `PROJECT_PROGRESS.md` — سجل التنفيذ والمهام المتبقية.
